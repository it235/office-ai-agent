# Office AI Agent 产品功能改进与 AI Native 战略调整报告

> **版本**：2026-10-24  
> **范围**：Word / Excel / PowerPoint 三端插件与 ShareRibbon  
> **方法**：设计文档 + 代码事实 + 用户旅程审计  
> **定位**：产品层战略报告。所有建议沿现有 `OfficeHarness -> AgentKernel -> LoopEngine -> ToolRegistry -> Host` 主链落地，不新建平行运行时。  
> **执行拆解**：[product-ai-native-strategy-execution-plan.md](./product-ai-native-strategy-execution-plan.md)（目标锁定、工作项、验收与防跑偏协议）

---

## 0. 一页结论

**一句话判断：插件已经具备 AI Native 的“骨架”，但用户拿到的仍然是“功能按钮 + 聊天框 + 不太敢让它自己动手的 Agent”。**

用户不会为“Harness”“Skill”“Tool”买单。用户只感知三件事：

1. **能不能一次做成**（任务完成率）
2. **做错了能不能退**（可控性与信任）
3. **下次还要不要重复说**（上下文与记忆）

当前这三点都还没有闭合。继续增加工具、按钮或聊天话术，边际收益已经很低；下一阶段的增长来自把“能力”变成“可托付的任务结果”。

### 三个必须发生的战略转向

| 转向 | 从 | 到 |
|---|---|---|
| 产品组织 | 以功能菜单组织（翻译/校对/排版/图表…） | 以用户任务组织（Job Pack，交付结果） |
| 执行体验 | 自动执行、黑盒修改、出错靠用户收拾 | 可控执行：预览、审批、取消回滚、一键撤销、解释 |
| 三端策略 | 三端各自堆能力、入口不对称 | 一个 Agent 内核 + 三套宿主场景包，Word 做深、Excel 补安全、PPT 补品牌与真实对象 |

### 北极星指标

> **无返工任务完成率（Task Success without Re-prompt）**：用户一次描述后，任务达到可接受结果，且不需要重新提示、手动修补或撤销的比例。

辅助指标：首次价值时间（Time to First Value）、平均修复次数、用户撤销率、7 日任务留存、单任务成本。

### 当前最痛的 5 件事

1. **改错了退不回**：Agent 级撤销未接通；取消/拒绝不回滚；replan 后可能重复写入。
2. **三端像三个产品**：大量入口被隐藏，能力不对称，模板库等入口实际不可达。
3. **不够懂当前文档**：Excel 只采样 8×8 预览；Agent 提示词中的长期记忆检索实际为空；会话不按宿主隔离。
4. **核心任务未闭环**：Excel 大表会卡死、预览是占位、失败不回滚；PPT 不复用母版、图表/表格是形状拼的、还存在假成功工具。
5. **首次价值太远**：没有引导向导；空 API Key 只在状态栏提示；费用、额度、隐私没有产品化。

## 1. 现状：真资产与真体验

### 1.1 应当保留的真资产

| 资产 | 现状 | 产品价值 |
|---|---|---|
| 统一 Agent 主链 | Harness → Kernel → Loop → ToolRegistry → 宿主执行 | 已有平台化基础，不需要推倒重写 |
| 结构化执行回执 | `ToolResult` 含错误码、可恢复性、Observation | 是“可信执行”的地基 |
| Skill + MCP + Memory | 目录型 Skill、MCP client、记忆管线 | 具备能力扩展与个性化潜力 |
| Word 闭环最深 | 快路径、快照 diff、UndoRecord、排版预览 | 可作为三端样板 |
| PPT 专业设计闭环 | Scene 语义、设计系统、真实渲染、视觉验证、标记式回滚 | 已是“一句话生成 Deck”的稀缺能力 |
| 本地执行 + 用户自带 Key | 不上传整份文档到自有云 | 隐私与成本差异化 |
| 视觉证据合规 | 截图只作临时内存证据，不落盘、不进 Trace | 可作为企业采购卖点 |

### 1.2 用户实际看到的产品

| 维度 | 现状 | 用户感受 |
|---|---|---|
| Ribbon | 共用 8 组入口，但 Word/Excel/PPT 各自隐藏不同按钮；模板排版等入口被隐藏 | “为什么同事的 Word 有，我的 Excel 没有？” |
| 聊天面板 | 已取消手动模式切换，统一智能路由（正确方向）；但用户仍面对一个空白输入框 | 不知道能做什么、该怎么问 |
| 模型切换 | 仅在设置弹窗内，无费用/额度提示 | “这一下要花多少钱？” |
| 历史会话 | 可新建/加载，但无重命名、无可靠删除、不按宿主过滤 | Excel 的会话混进 Word 历史 |
| 首次使用 | 静态说明卡；默认 Provider 但 Key 为空；发送时才在状态栏提示 | 第一次就受挫 |
| 隐私 | `PrivacyPolicyAccepted` 字段存在，但没有界面与调用 | 企业用户无法确认数据边界 |
| 免费入口 | Deepseek/Doubao 是独立内嵌网页，与主面板的模型、历史、MCP、工具链割裂 | 两个产品，体验断裂 |
| 面板外入口 | 无右键菜单、无全局快捷键、无选区浮动工具条；自动补全默认关闭且入口隐藏 | 必须“打开面板—描述—发送”，不符合 Office 工作流 |

### 1.3 关键代码事实与产品影响

| 事实 | 证据 | 产品影响 |
|---|---|---|
| Loop 硬上限 15 次迭代，修复 3 次，replan 2 次 | `ShareRibbon/Agent/LoopEngine.vb:22-24` | 超过 15 步的复杂任务会整体失败，用户只看到“任务失败” |
| replan 后按新计划从第 0 步重跑 | `ShareRibbon/Agent/LoopEngine.vb:351-357` | 已完成的写入可能被重复执行 |
| 审批“拒绝”返回不可恢复失败 | `ShareRibbon/Agent/LoopEngine.vb:181-205` | “跳过这一步”实际会终止整轮任务 |
| 取消只在不打断 COM 的安全点生效，且不回滚 | `ShareRibbon/Agent/LoopEngine.vb:446-455` | 用户停止后文档留下半成品，且无提示如何还原 |
| `UndoPointId` 只有定义，没有任何赋值 | `ShareRibbon/Agent/ToolRegistry.vb:70,94` | “撤销本轮”只是文案，没有真实能力 |
| Agent 提示词中的记忆检索为空查询 | `ShareRibbon/Agent/PromptManager.vb:142`；`AgentMemory.vb:227` | 长期记忆形同虚设，用户仍要重复偏好与背景 |
| 历史会话查询不按 `app_type` 过滤 | `ShareRibbon/Storage/ConversationRepository.vb:100-106` | 三端会话互相污染，找不到当前文档的上下文 |
| Excel 清洗逐单元格遍历，无分块/进度/取消 | `ExcelAi/ExcelDirectOperationService.vb:735-777` | 十万行数据会长时间占用 UI/COM，表现为假死 |
| Excel 失败后明确不回滚 | `ExcelAi/ChatControl.vb:1198-1245` | 用户只能手工收拾半应用结果 |
| PPT 内置主题只弹提示却返回成功 | `PowerPointAi/ChatControl.vb:2455-2469` | 典型的“假成功”，直接损害信任 |
| PPT 生成始终新建 Blank 版式，不复用母版 | `PowerPointAi/Design/PowerPointSceneRenderer.vb:32` | 无法套用企业模板，品牌一致性差 |
| 默认 Excel Skill 的 `allowed-tools` 不含 `CreateSheet`/`InsertRowCol` 等结构操作 | `ShareRibbon/Skills/excel-table-agent/SKILL.md` | 用户说“把结果放到新 Sheet”，模型规划后会被硬拒绝 |
| 默认 PPT Skill 不含 `DeleteSlide`/`InsertShape`/`DuplicateSlide` 等 | `ShareRibbon/Skills/powerpoint-deck-agent/SKILL.md` | 常见的“删掉这页/复制这页/插个形状”无法执行 |
| Excel Skill 正文建议用 `ExecuteVBA` 兜底，但 VBA 被策略禁用且不在 allowed-tools | `ShareRibbon/Skills/excel-table-agent/SKILL.md` | 模型会规划一条必然失败的路径 |
| 自动补全默认关闭 | `ShareRibbon/Config/ChatSettings.vb:24-27` | 内联写作辅助能力未上线 |

## 2. 七个产品级问题

### P0-1 信任断层：能改，但用户不敢用

**现象**：Agent 可以真实修改文档，但缺少“改前可预览、改中可停止、改后可撤销”的完整闭环。

- 取消后不回滚，只提示“已完成 N 个操作”（`LoopEngine.vb:446-455`）。
- 审批拒绝等于整轮失败，而不是跳过该步。
- `UndoPointId` 从未赋值，UI 上的“撤销点”只是文字。
- replan 从第 0 步重跑，存在重复写入风险。
- RunTrace 已落库，但没有任何回放/时间线 UI。

**用户后果**：用户只敢让 AI 做“读”或“小改”，不敢让它独立完成长任务。这直接扼杀了“本地真实执行”这一核心差异化。

**产品判断**：这是当前第一优先级，不是工程洁癖。没有信任层，能力越多，风险越大。

---

### P0-2 三端体验断层：像三个不同公司的产品

**现象**：

- Word 隐藏数据分析、聚光灯、批量生成；Excel 隐藏校对、排版、续写、网页抓取；PPT 隐藏校对、排版、数据分析、抓取。
- 校对、排版只在 Word 可见；PPT 没有等价的智能排版入口。
- 翻译三端各自实现，术语表、批处理、预览体验不一致。
- 模板库入口被隐藏，三端都难以发现。
- Deepseek/Doubao 独立网页与主面板割裂。

**用户后果**：迁移到另一个 Office 应用时能力“消失”，学习成本与支持成本上升，品牌认知不一致。

**产品判断**：不必强求三端功能完全一样，但必须做到“同一类任务在三个宿主里有一致的入口、一致的解释、一致的结果承诺”。

---

### P0-3 上下文与记忆不连续：用户觉得“它不懂我的文档”

**现象**：

- Excel 上下文只做 8×8 选区预览与 30 行类型抽样，缺少表区域、公式依赖、错误单元格定位。
- Agent 提示词中的记忆检索是空查询，实际永远拿不到记忆（`PromptManager.vb:142`）。
- 会话列表不按宿主过滤，Excel 会话会出现在 Word 历史里（`ConversationRepository.vb:100-106`）。
- Agent 轮没有与普通聊天同等的结构化记忆抽取，任务经验难以沉淀。

**用户后果**：每次都要重新说明“这是哪个表、哪一列、我习惯什么格式”，Agent 不会越用越懂。

**产品判断**：上下文与记忆是智能感的来源，优先于再增加十个工具。

---

### P0-4 核心任务闭环缺失：三个宿主各有一个“断点”

**Word**：能力最深，但确定性快路径绕过 Loop，导致审批、观察、撤销、Trace 标准不统一。用户会觉得“有时候能撤销，有时候不能”。

**Excel**：

- 大表无分块、无进度、无取消，容易假死。
- 预览只列命令，单元格 old/new 是占位符。
- 失败明确不回滚。
- 缺少表区域探测与公式依赖理解，“分析报告”难以真正闭环。

**PowerPoint**：

- 不复用母版/企业模板，始终 Blank 版式重画。
- 图表、表格由形状拼装，用户无法改数据系列。
- `ApplyTheme`、`AddSpeakerNotes`、`SetSlideLayout` 存在假成功或硬编码对象。
- 写入前没有视觉预览（`ScenePlanPreviewRenderer` 未接入生产）。
- 单页失败会整副回滚，重生成成本高。

**产品判断**：三端各自补齐一个“必须闭环”的核心任务，比同时铺开十个半成品更有价值。

---

### P0-5 入口不贴合 Office 工作流

**现象**：没有选区浮动工具条、没有右键“AI 处理”、没有全局快捷键、没有命令面板；自动补全默认关闭；选区自动引用默认关闭。

**用户后果**：AI 被隔离在右侧面板里，用户必须中断当前动作，打开面板、打字、发送。与 Copilot 的“就地出现”体验差距明显。

**产品判断**：AI Native 不只是“能执行”，还包括“在用户需要的地方、以最小的动作出现”。

---

### P0-6 首次价值与商业体验缺失

**现象**：

- 无引导向导；默认 Provider 但 Key 为空，发送失败后才在状态栏提示。
- 无费用预估、额度、Token 预算提示。
- 隐私开关只有字段，没有界面。
- 免费入口与主产品割裂。

**用户后果**：激活率低、首次体验受挫、企业采购缺乏可解释的数据边界。

**产品判断**：这是增长问题，不只是 UI 问题。首次 60 秒决定用户是否继续。

---

### P1-7 能力边界与对外宣称不一致

**现象**：

- 默认 Skill 的工具边界过窄，常见的“新建 Sheet / 删除幻灯片 / 插入形状”被硬拒绝。
- Skill 正文建议 VBA 兜底，但 VBA 被禁用且不在 allowed-tools。
- 部分 Ribbon 入口被隐藏，用户可见能力与真实能力不一致。
- 文档、提示词、Skill、工具注册表存在多处“同一能力集”的漂移风险。

**用户后果**：模型会规划出“必然失败”的步骤，用户看到“暂不支持”，但同类操作在 Ribbon 上其实存在。

**产品判断**：能力边界必须成为产品配置的一部分，而不是散落在四份文件里的隐式规则。

---

### P1-8 没有评测与反馈闭环

**现象**：已有 smoke 与 L0 契约检查，但没有真实 Office 文档的黄金任务集，没有产品内的“接受/拒绝/哪里不对”反馈，也没有任务成功率埋点。

**用户后果**：团队无法判断“是否变聪明了”，每次改动靠感觉；回归只能在真机手工发现。

**产品判断**：AI Native 产品的迭代速度取决于评测闭环。没有度量，就没有战略。

## 3. 战略调整：从“AI 功能插件”到“Office 任务代理”

### 3.1 产品分层

| 层 | 用户动作 | 产品形态 | 成功标准 |
|---|---|---|---|
| Assist（辅助） | 选中内容，点一下 | 选区工具条、右键菜单、内联建议 | 1 次点击得到可用结果 |
| Execute（执行） | 说一句话 | Agent 计划 → 执行 → 观察 → 解释 | 无需返工完成任务 |
| Operate（运营） | 批量/周期性 | 任务包、模板、批处理、报表 | 可重复、可审计、可撤销 |

当前产品几乎全部压在 Execute 层，Assist 层基本缺失，Operate 层刚起步。三层补齐后，用户才会觉得“到处都能用”。

### 3.2 任务包（Job Pack）：AI Native 的产品组织单位

**定义**：一个任务包 = 触发入口 + 上下文读取 + Skill 手册 + 允许工具 + 预览策略 + 验证器 + 交付物 + 解释模板。

用户不需要理解“工具”“Skill”“Agent”，只需要选择或直接说出一个工作目标。

| 宿主 | 任务包 | 用户一句话 | 交付物 | 成功标准 |
|---|---|---|---|---|
| Word | 审阅润色 | “把这份报告润色成给老板看的版本” | 修订稿 + 问题清单 | 保留原意、格式不乱、可逐条接受 |
| Word | 模板排版 | “按公司模板重排全文” | 排版后的文档 | 标题/正文/编号/页眉页脚一致 |
| Word | 长文写作 | “根据提纲写完整章节” | 分段写入的正文 | 结构连贯、引用当前文档风格 |
| Word | 合同/报告检查 | “看看这份合同有哪些风险条款” | 风险清单 + 定位 | 每条可跳转、可解释 |
| Excel | 表格问答与洞察 | “这张表说明了什么？” | 结论 + 关键指标 + 图表 | 数据准确、引用单元格可追溯 |
| Excel | 清洗与公式修复 | “把这张表清洗干净并修好公式” | 清洗结果 + 错误报告 | 可预览、可撤销、不破坏原表 |
| Excel | 透视与图表报告 | “按区域和月份做汇总” | 新 Sheet + 透视/图表 | 不改源数据、结果可刷新 |
| Excel | 批量/周期报表 | “每周按这个模板生成报表” | 批量结果 + 日志 | 可重复、失败可定位 |
| PPT | 一句话成稿 | “做一份 8 页的季度汇报” | 完整 Deck | 结构合理、视觉一致、可编辑 |
| PPT | 文档转 Deck | “把这份 Word 变成汇报 PPT” | Deck + 讲稿 | 提炼准确、页数可控 |
| PPT | 品牌模板美化 | “套用公司模板并统一风格” | 美化后的 Deck | 复用母版、品牌 token 一致 |
| PPT | 讲稿与备注 | “给每页写演讲备注” | 备注 + 讲稿 | 与页面内容对应、语气一致 |

**落地要求**：每个任务包必须有独立的验收标准与黄金样例；不允许只写 Prompt 就算完成。

### 3.3 信任层：让用户敢把文档交给 Agent

这是本报告认为**最高优先级**的产品能力，也是与普通“AI 生成器”的分水岭。

| 阶段 | 必须提供的产品能力 | 用户可感知的文案 |
|---|---|---|
| 执行前 | 计划卡：改哪里、改多少、风险级别、是否可撤销；支持编辑计划 | “准备修改第 3–17 段，共 14 处，可撤销” |
| 执行中 | 步骤时间线、当前步骤、进度、随时停止 | “正在处理第 3/7 步：统一标题样式” |
| 执行后 | 变更摘要、文档内高亮/对比、为什么这么做、一键撤销本轮 | “已修改 14 处，[查看变更] [撤销本轮]” |
| 失败/取消 | 明确已完成与未完成；提供回滚或保留选择 | “已停止，已写入 3 处，[撤销这 3 处] [保留]” |
| 审批 | 允许一次 / 本会话允许该工具 / 拒绝；拒绝只影响当前步骤 | “是否允许删除 2 个工作表？” |

**产品宪法**：任何写操作，都必须能回答三个问题——改了什么、能不能退、为什么这么改。做不到，就不允许自动执行。

### 3.4 上下文与记忆：先读后想，越用越懂

| 能力 | 目标 |
|---|---|
| 文档结构快照 | Word：标题树/节/域；Excel：表区域/列类型/公式依赖/错误单元格；PPT：母版/版式/页面大纲 |
| 渐进式上下文 | 先给摘要与大纲，需要细节时通过读工具二次拉取，避免一次塞爆上下文 |
| 文档级记忆 | 记忆绑定到文档与宿主，而不是全局混杂；同一文档下次打开能延续约定 |
| 用户偏好记忆 | 字体、字号、语气、公司术语、常用模板，结构化保存并可管理 |
| 会话隔离 | 会话按宿主 + 文档过滤；支持重命名、删除、搜索 |
| 记忆可见可控 | 用户能看到“记住了什么”，能删除、导出、关闭 |

**关键原则**：记忆不是 RAG 装饰，而是 Agent 减少重复提问的手段。记不住，就不要假装记得。

### 3.5 三端策略：一核三专，不平均用力

| 宿主 | 战略定位 | 当前要补的核心 | 不建议现在做 |
|---|---|---|---|
| Word | 最深、最可信的文档代理 | 信任层统一、模板排版产品化、长文写作 | 追平 Excel 的数据分析 |
| Excel | 安全的数据分析代理 | 大表安全执行、真实预览与回滚、表理解、公式修复 | 完整 PowerQuery、复杂建模 |
| PowerPoint | 品牌化的演示代理 | 母版/企业模板、原生图表表格、写入前预览、单页重生成 | 为每种版式新增专用 Tool |

三端共享：入口规范、信任层、任务包框架、评测体系、记忆与上下文合同。  
三端分离：COM 执行、Catalog、Observer、模板与宿主特有语义。

### 3.6 入口策略：让 AI 在用户工作的地方出现

按优先级：

1. **选区浮动工具条**：选中文本/单元格/形状后，出现 3 个最可能的动作（润色、解释、格式化）。
2. **右键菜单**：“AI 处理选中内容”“解释这段”“按模板排版”。
3. **全局快捷键 / 命令面板**：一个快捷键唤起，支持自然语言与命令。
4. **内联 ghost text**：在观察期后重新开放，默认关闭、可配置、可度量。
5. **主动建议**：文档打开时最多 1 条高置信建议（如“发现 3 处标题层级不一致”），必须可关闭。
6. **一个输入框为默认**：高级模式渐进披露，不要求用户先选模式。

## 5. 90 天路线图

### Phase 1（第 1–4 周）：可信与一致

**目标**：让用户敢用、找得到、不串端。

- T1 本轮撤销与取消回滚（先 Word，再 Excel/PPT）
- T2 会话与文档绑定
- T7 首次 60 秒向导
- T8 选区工具条 + 右键菜单 + 快捷键（先各端一个最小入口）
- T9 能力一致性治理，移除或修复假成功与不可达入口
- T10 Word 快路径纳入统一信任层

**退出标准**：

- 取消任意任务后，用户能一键还原本轮修改。
- 任一宿主的历史只显示本宿主/本文档会话。
- 新用户从安装到完成第一个任务 ≤ 60 秒。
- 所有可见入口都有真实能力，不存在“点了没反应/提示暂不支持”。

### Phase 2（第 5–8 周）：任务闭环

**目标**：把 6 个高频任务真正做到“一次说清、一次做成”。

- T11 前 6 个任务包（Word 审阅/排版，Excel 清洗/洞察，PPT 成稿/模板）
- T3 + T4 Excel 大表与预览回滚
- T5 + T6 PPT 品牌模板、原生图表、写入前预览
- T12 计划可编辑与单步重试
- T16 黄金评测集 v1

**退出标准**：

- 6 个任务包在真实文档上的无返工完成率 ≥ 60%。
- Excel 十万行任务不冻结 UI，且可取消。
- PPT 能复用至少 1 套母版模板，图表为原生对象。
- 每个任务包有可复现的黄金样例与失败样例。

### Phase 3（第 9–12 周）：智能与生态

**目标**：从“能完成”到“越用越懂、可扩展”。

- T13 文档级记忆与偏好记忆
- T14 上下文深度
- T15 运行时间线与回放
- T17 产品内反馈 + 指标看板
- T18 成本与模型路由
- T19 首个 MCP 连接器 / T20 模板市场试点

**退出标准**：

- 同一文档的第二次任务，用户重复说明减少 ≥ 30%。
- 任务成功率、修复次数、撤销率可按宿主/任务包查看。
- 至少 1 个外部数据源可通过 MCP 参与真实任务。

## 6. 度量体系

### 6.1 指标

| 层级 | 指标 | 目标（3 个月） |
|---|---|---|
| 北极星 | 无返工任务完成率 | ≥ 60% |
| 激活 | 首次价值时间 | ≤ 60 秒 |
| 质量 | 平均修复次数 | ≤ 1.0 |
| 信任 | 用户撤销率 | ≤ 15% |
| 留存 | 7 日任务留存 | 基线 +20% |
| 效率 | 单任务平均步数 | 下降 20% |
| 成本 | 单任务平均 Token | 可解释、可按任务包对比 |
| 安全 | 未授权写入 / 假成功 | 0 |

### 6.2 埋点建议

本地优先、可选上报：

- `task_start` / `task_complete` / `task_cancel` / `task_fail`
- `plan_shown` / `plan_edited`
- `approval_shown` / `approval_allow_once` / `approval_allow_session` / `approval_reject`
- `step_result`（tool、error_code、耗时、repair 次数）
- `undo_this_run`
- `feedback`（接受/拒绝/原因标签）
- `time_to_first_value`

## 7. 明确不做

1. **不继续增加工具数量**。长尾能力继续走 `DiscoverOfficeCapability + OfficeObjectOperation`，不要一需求一 Tool。
2. **不新建第二套 Harness / Loop / Safety / 执行入口**。所有改进沿现有主链。
3. **不追 Copilot 365 的全量企业能力**。先做本地真实执行 + 可信可控。
4. **不做无审批的高风险自动执行**。删除、整表替换、VBA、取消保护必须可控。
5. **不把所有交互都塞进聊天框**。Assist 层必须就地出现。
6. **不做“看起来智能”的假成功**。宁可明确失败，也不虚报完成。

## 8. 未来两周的 6 个动作

1. **冻结“信任合同”**：写下写操作的预览/审批/观察/撤销/取消规范，并选 Word 做第一个闭环。

5. **建立 20 个真实文档黄金任务**：覆盖三端，带成功标准与失败样例。
6. **做一次能力一致性审计**：Skill / Tool / Prompt / Ribbon 四份清单对齐，修掉“说得到做不到”。
